# Project Planning Skill

Before design/coding, Cline MUST prepare a plan proportionate to the project's size and risk and create or update these files in `docs/01-plan/`: `PRD.md`, `scope.md`, `WBS.md`, `roadmap.md`, `risks.md`. Use the `templates/PRD-template.md` template.

## Required Method

1. Clarify the problem need, users, evidence, and success criteria. State goals as SMART (Specific, Measurable, Achievable, Relevant, Time-bound).
2. In the PRD, record the problem, users/personas, functional and non-functional requirements, priorities, acceptance criteria, dependencies, assumptions, and out-of-scope items.
3. Separate scope into in-scope and out-of-scope. Turn ambiguous requests into questions; do not add hidden scope.
4. Break the WBS into small, estimable and verifiable deliverables and tasks; for each, specify an ID, dependency, owner/role, estimate, acceptance criterion, and status.
5. Present the roadmap with milestones, order/dependencies, time windows or estimated durations, decision points, and measurable outputs; do not present estimates as certainties, and state uncertainty/capacity.
6. Maintain a risk register with ID, likelihood, impact, score/priority, trigger, owner, and preventive/contingency action; consider security, privacy, data, third parties, and deployment.
7. For significant technology choices, create an ADR covering context, options, criteria, decision, consequences, and status. Do not finalize a decision without the end user unless explicit authority has been given.
8. Define the Definition of Done (DoD) to include implementation, testing, coverage, documentation, security, review, and acceptance criteria.

Before design, Cline MUST check scope coverage, whether goals are SMART, WBS completeness, milestones, critical risks, estimates, and DoD. At the end of planning, run the master-rules checkpoint.
